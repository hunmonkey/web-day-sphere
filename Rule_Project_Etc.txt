============================================================
프로젝트 아키텍처 및 폴더 구조 가이드
============================================================

이 문서는 AI 에이전트와 새로운 개발자가 프로젝트의 전체적인 구조를 
빠르게 파악하고 일관성 있게 코드를 작성하도록 돕는 핵심 길잡이입니다.
새로운 요구사항을 구현하기 전, 반드시 이 문서를 참조하여 알맞은 폴더와 방식을 선택하세요.


★★★ 절대 원칙 — 한 화면 고정 (스크롤 금지) ★★★
------------------------------------------------------------
이 규칙은 디자인·기능 어떤 요구보다도 우선한다. 새 화면·컴포넌트를 추가할 때 반드시 이 규칙부터 검증한다.

- 모든 화면은 브라우저 한 화면(뷰포트)에 정확히 들어맞아야 한다.
- 페이지(뷰포트)가 위아래로 내려가거나 좌우로 밀리는 스크롤은 절대 발생시키지 않는다.
- 콘텐츠가 많아지면: 탭 / 화면 분할 / 요약 / 고정 영역 내부 스크롤로 처리하되,
  화면(뷰포트) 자체는 절대 움직이지 않게 한다. (페이지 스크롤 금지, 패널 내부 스크롤은 허용)
- 레이아웃은 100vh / 100vw 안에 고정하고, 카드·패널 높이를 화면에 맞춰 분배한다.
- body/루트에 페이지 스크롤이 생기지 않도록 높이를 고정(예: h-screen + overflow-hidden)한다.


0. 공통 작업 지침
------------------------------------------------------------
- `AGENTS.md`와 `CLAUDE.md`는 이 프로젝트뿐 아니라 모든 작업의 기본 지침입니다.
- 작업 행동, 호칭, 배포, 보안, 터미널 안전 규칙은 두 문서를 우선 적용합니다.
- 프로젝트 루트의 `AGENTS.md` / `CLAUDE.md` 사본은 전역 기준 파일과 같은 내용으로 유지합니다.
- 개발, 수정, 테스트 작업은 원칙적으로 `dev` 브랜치에서 진행합니다.
- 사용자가 GitHub 최신화/연동을 요청하면 `main`과 `dev` 브랜치를 모두 최신 커밋으로 맞춰 푸시합니다.


1. 인증 및 사용자 계정
------------------------------------------------------------
- 앱 첫 실행 시 `/`에서 초기 관리자 계정을 만든 뒤 로그인 화면으로 보호합니다.
- 로그인 세션은 `day_sphere_session` 서버 쿠키로 유지합니다.
- 사용자/세션 데이터는 루트의 `.day-sphere/auth.json`에 저장하며, 비밀번호는 원문이 아니라 해시로 저장합니다.
- `.day-sphere/`는 민감한 서버 데이터 폴더이므로 Git 커밋에서 제외합니다.
- 관리자만 앱 안의 `사용자` 탭에서 허용 사용자 추가, 활성/비활성 전환, 권한 변경, 비밀번호 재설정, 삭제를 할 수 있습니다.


2. Markdown(Vault)을 1차 저장소로 (Obsidian/Syncthing 연동)
------------------------------------------------------------
- 할일·캘린더·메모·알람·손글씨 등 모든 데이터의 "원본"은 Markdown 파일(Vault)이다.
  앱 시작 시 `GET /api/vault`로 읽어 상태를 채우고, 변경 시 debounce 후 `PUT /api/vault`로 자동 저장한다.
  localStorage(`ds.*`)는 즉시 캐시 + 최초 마이그레이션 소스 + 서버 미응답 시 폴백일 뿐 원본이 아니다.
- 기본 저장 위치는 `.day-sphere/obsidian-vault`. 실제 Obsidian Vault(Syncthing 동기화 폴더)에 직접 쓰려면
  서버 실행 전에 `DAY_SPHERE_OBSIDIAN_DIR` 환경변수로 대상 폴더를 지정한다. 앱은 반드시 Node 서버(`next start`)로 구동.
- 파일 구조:
    Calendar/YYYY-MM-DD.md   날짜별 할 일(GFM 체크박스, `^id` 블록참조로 무손실·Obsidian 편집 양방향)
    Memos/<id>.md            메모 텍스트(+손글씨 변환 결과). frontmatter에 id/created/ink 경로
    _assets/<id>.ink.json    손글씨 획 원본(무손실, 캔버스 재편집용)
    _assets/<id>.svg         손글씨 표시용(메모 md에서 `![[...]]`로 임베드)
    Alarms.md                알람(frontmatter가 원본, 표는 표시용)
- 무손실 라운드트립 + 멱등 저장(내용 동일 시 미기록)이 원칙. 충돌은 "최근 수정 우선":
  외부(Obsidian/Syncthing)에서 더 최근에 수정된 파일은 덮어쓰지 않고 충돌로 보고한 뒤 그쪽을 다시 읽어온다.
- 핵심 파일: `src/lib/server/vault-store.ts`(읽기/쓰기), `src/app/api/vault/route.ts`(GET/PUT),
  `src/components/vault/vault-provider.tsx`(클라이언트 동기화), `src/lib/vault-types.ts`(공용 타입).
- (구) `POST /api/obsidian/export`는 새 모델로 대체되어 UI에서 더 이상 호출하지 않는다(별도 레이아웃이라 정리 대상).

2-1. 손글씨 → 타이핑 텍스트 변환 (오프라인)
------------------------------------------------------------
- 브라우저 내장 Handwriting Recognition API(`navigator.createHandwritingRecognizer`)로 변환. 외부 전송·API 키 없음.
- 지원 여부는 `src/lib/handwriting.ts`의 `checkHandwritingSupport()`로 감지(주로 Chromium + 해당 언어 모델 필요).
  미지원 환경은 버튼 비활성화 + 안내, 손글씨는 SVG로만 저장. 변환 결과는 메모 텍스트에 누적되어 md로 저장된다.

2-2. 외부 내보내기 (PDF / SVG / JPG)
------------------------------------------------------------
- 손글씨: SVG/JPG로 다운로드(`src/lib/export-image.ts`, 클라이언트, 의존성 0). SVG 렌더는 `src/lib/ink-svg.ts` 공용.
- 할일·캘린더 / 메모 텍스트: 인쇄 창을 띄워 "PDF로 저장"(`src/lib/export-pdf.ts`). 한글은 시스템 폰트로 렌더(폰트 번들 불필요).
