============================================================
AI 작업 인수인계용 진행 기록 / To-Do
============================================================

이 파일은 사람(황재훈 님)과 AI, 그리고 AI들 사이의 "프로그램 개발 작업 전용 메모장 + 투두리스트"입니다.
사전 정보가 전혀 없는 AI라도 이 파일을 읽고 어떤 작업을 이어서 해야 하는지 파악해 일관되게 이어갈 수 있어야 합니다.
짧고 정확하게 기록한다.


------------------------------------------------------------
■ 이 파일의 사용 규칙 (AI는 반드시 지킬 것)
------------------------------------------------------------
1. 프로그램 개발 작업을 시작하기 전에 작업 계획, 단계, 내용에 대해 기록한다.
   단, 이 파일에는 프로그램 개발, 코드 수정, 테스트, 기능 구현처럼 실제 제품을 만드는 작업만 기록한다.
   GitHub 최신화/연동, 브랜치 동기화, 단순 상태 확인, 작업 기록 정리 같은 관리 작업은 기록하지 않는다.
2. 기록을 할 때 현재상태, 작업 제목, 날짜 및 시각 (YYYY-MM-DD HH:MM:SS), 어디, 무엇/어떻게, 검증을 기록한다. (상태는 대기, 진행, 완료, 실패 4가지 중 하나를 사용한다.)

(예시)

[완료] 2-1. 데이터 폴더 방식 전환  (2026-05-31 14:30:31)
  어디: papastop.py
  무엇/어떻게:
   · APP_CACHE_DIR 폴더명을 ".papastop_cache" → ".papastop_data" 로 변경.
   · prepare_cuda_library_path(): EXE에서 _MEIPASS 번들 대신 외부 APP_CACHE_DIR/"nvidia"에서 CUDA를 찾도록 변경.
   · nllb_model_dir(): EXE 번들(_MEIPASS) 분기를 제거하고 항상 외부 폴더(NLLB_MODEL_DIR) 사용.
   · Whisper는 원래부터 외부 HF 캐시(.papastop_data/huggingface)를 쓰므로 변경 없음.
   · 개발 폴더 .papastop_cache → .papastop_data 로 이름 변경(데이터 보존).
  검증: _MEIPASS 잔존 참조 없음 확인. is_frozen_app은 다른 곳에서 계속 사용되어 유지.

3. 기록한 개발 작업은 순서대로 진행하며 [대기] 상태의 작업을 [진행]으로 변경한 후 작업 진행한다. (진행은 항상 하나만 둔다.)
4. [진행] 상태의 개발 작업을 완료한 이후 상태를 [완료]로 변경하며 다음 순서의 [대기] 작업을 [진행]으로 변경한 후 이어서 작업 진행한다.
5. 기록한 개발 작업의 상태가 모두 [완료] 또는 [실패]로 변경되면 '작업 진행 계획'에 있는 내용 전체를 루트 폴더의 'Rule_ToDo_Done.txt' 파일로 이동시킨다. (완료와 실패가 섞여있어도 이동)
6. '작업 진행 계획'은 다음 질문에 대한 작업을 위하여 깨끗이 비워둔다.
7. 파일명·함수명은 정확히 적는다. (줄 번호는 코드가 바뀌면 어긋나므로 함수명 위주로 쓴다.)
8. 추정이 아니라 확인된 사실을 적는다. 확인 못 한 것은 "미검증"이라고 표시한다.
9. 비밀번호, 토큰, 개인 키, Rule_PW.txt 내용 같은 민감정보는 절대 기록하지 않는다.

■ 프로젝트 한 줄 요약
------------------------------------------------------------
Next.js(App Router, TypeScript) + Tailwind + Framer Motion 기반 프리미엄 통합 대시보드(To-do/캘린더/알람/메모).
DB는 Unraid Docker PostgreSQL + Prisma, 실시간 동기화는 SSE, 알림은 PWA 웹푸시. Cloudflare Tunnel로 외부 접속.
