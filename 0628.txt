[아날로그 시계(analog-clock.tsx) 설계]
- 순수 SVG로 시·분 바늘(+초침 표시)을 그린다(외부 라이브러리 0). 12시간 눈금.
- props: { time?: "HH:MM:SS", active:boolean }
  · active=true(등록됨): 정상 색(글자·선색 + 핵심 액션색 포인트). 바늘이 등록 시각을
    가리킨다.
  · active=false(미등록): 전체를 회색(neutral)으로 흐리게(opacity 낮춤) = "비활성" 표현.
- 크기: 한 화면 5개가 세로로 들어가야 하므로 작게(지름 약 56~72px). 박스 높이에 맞춰
  반응형으로 축소.

[자리별 시간 증감 입력(time-spinner.tsx) 설계 — 결정 반영]
- 표시: H H : M M : S S  (총 6개의 한 자리 숫자 칸, 콜론 2개로 구분)
- 각 숫자 칸은 세로 3단:
    윗줄:  ▲ (위 삼각형 버튼)
    가운데: 그 자리 숫자 1개 (예: 시의 십의자리 "1")
    아랫줄: ▼ (아래 삼각형 버튼)
  → 삼각형은 자리마다 위·아래 1쌍씩, 총 6쌍.
- 동작(요청 그대로): 그 "자리"의 숫자만 1씩 오르내린다.
  · 예) 시(HH)의 앞 칸(십의자리) ▲ 를 누르면 십의자리 숫자가 0→1→2 처럼 1 증가.
        화면 숫자는 "1"만 오른 것이지만 실제로는 10시간 단위가 바뀐 것.
  · 일의자리 ▲ 를 누르면 일의자리만 0→1→...→9 처럼 1 증가.
- 자리별 순환 범위(24시간제, 유효 시각 보장):
  · 시 십의자리: 0 → 1 → 2 → 0 (순환)
  · 시 일의자리: 0~9 순환. 단 십의자리가 2이면 0~3까지만(23시 초과 방지).
  · 분/초 십의자리: 0~5 순환
  · 분/초 일의자리: 0~9 순환
  · 십의자리를 올려 결과가 무효가 되면(예: 시 십의자리를 2로 올렸는데 일의자리가 4~9)
    일의자리를 유효 최대값으로 자동 보정한다.
- ▼ 는 ▲ 의 반대 방향 1 감소(0에서 누르면 그 자리 최대값으로 순환).
- 접근성(Rule_UIUX 1-4): 삼각형 버튼마다 aria-label(예: "시 십의자리 1 증가"),
  Tab 이동·포커스 표시 유지. 색만으로 구분하지 않는다.

[알람 슬롯 박스(alarm-slot.tsx) 설계]
- 가로 배치: [아날로그 시계] [HH:MM:SS 자리별 증감 입력] [버튼 묶음]
- 버튼 묶음(세로 또는 가로):
  · 등록: 핵심 액션색(파랑). 미등록 상태에서만 활성. 누르면 알람 고정 + 시계 활성.
  · 초기화: 보조 톤. 등록 상태에서만 활성. 누르면 알람 제거 + 시계 비활성 + 입력 리셋.
- 상태 표시(Rule_UIUX 2-1: 색만으로 구분 금지):
  · 미등록: 시계 회색 + 작은 글자 "대기"
  · 등록됨: 시계 컬러 + 작은 글자 "켜짐"
- 한 박스 높이가 작으므로 시계/숫자/버튼 크기를 콤팩트하게. 5개가 세로로 화면 안에
  반드시 들어가도록 높이를 (좌측 영역 높이 ÷ 5)에 맞춰 분배.

[알람 탭 전체 레이아웃(alarm-tab.tsx)]
- 2단 구성:
    좌측: 다이얼 알람 박스 5칸(세로 1열) — 신규.
    우측: 기존 알람 카드(다음 알람 / 시간 입력 폼 / 빠른 추가 / 알람 목록) — 그대로 유지.
- 한 화면 고정: 좌측 5칸 + 우측 카드가 100vh 안에 들어가도록 높이 분배. 넘치면 패널
  내부 스크롤만 허용(페이지 스크롤 금지).
- 모바일: 2단이 좁으면 위(좌측 5칸)·아래(우측 카드) 또는 우측 카드 우선 등 단을
  쌓는 방식으로 대응(페이지 스크롤은 금지, 패널 내부 스크롤 허용).

[검증 기준]
- 좌측에 박스가 정확히 5개, 세로 1열로 보인다.
- 자리별 ▲/▼ 로 각 자리 숫자가 규칙대로 1씩 증감·순환하고, 무효 시각이 만들어지지
  않는다(예: 23시 초과 불가).
- 등록 → 해당 시각 알람이 켜지고 시계가 컬러로 활성, 그 시각에 실제로 알람이 울린다.
- 초기화 → 알람이 사라지고 시계가 회색 비활성, 입력이 리셋된다.
- 좌측에서 등록한 알람이 우측 목록에도 보이고, 우측에서 삭제하면 좌측 박스도 비활성
  된다(좌·우 동기화).
- 새로고침/다른 기기 접속 후에도 등록한 알람이 유지된다(Vault 저장 확인).
- 페이지 스크롤이 생기지 않는다.

5. 작업 순서 (검증 가능한 단계)
--------------------------------------------------------------------------------
1) (요청 3·4) 탭/제목 라벨 "플래너" 변경 → 검증: 탭·설정 라벨 표기 확인.            [소]
2) (요청 4) 메모 안내 문구 2곳 삭제 → 검증: 빈 상태에서 문구 없음·기능 정상.        [소]
3) (요청 2) 헤더 한 줄 통합 → 검증: PC에서 한 줄, 본문 높이 증가, 스크롤 없음.      [중]
4) (요청 1) 각 탭 여백 미세 정리로 입력 영역 최대화 → 검증: 한 화면 유지.           [소]
5) (요청 5) 알람 신규 컴포넌트 3종 제작 + 알람 탭 2단 재구성 → 검증: 위 알람 기준.   [대]
   - 5-1 time-spinner(자리별 증감 입력) 단독 제작·검증
   - 5-2 analog-clock(활성/비활성) 단독 제작·검증
   - 5-3 alarm-slot(시계+입력+버튼+등록/초기화) 조립·검증
   - 5-4 alarm-tab 좌측 5슬롯 + 우측 기존 카드 유지 + 좌·우 Vault 동기화 검증
* 위험도가 낮고 효과가 빠른 1~4를 먼저 끝내고, 큰 작업(5)을 마지막에 집중 진행.

6. 확정된 결정 사항 (2026-06-28, 황재훈 님)
--------------------------------------------------------------------------------
(1) 삼각형 증감 단위 = "자리수 단위(+1)".
    - HH:MM:SS 각 숫자 칸(자리)마다 위·아래 삼각형(총 6쌍).
    - 그 자리 숫자만 1씩 증감(예: 시 십의자리 ▲ → 0→1→2, 실제로는 10시간 단위 변화).
(2) 알람 탭 우측 = 기존 알람 박스를 그대로 사용(좌측은 신규 다이얼 박스 5칸).
(3) 첫 번째 탭 표시 이름 = "플래너"(내부 ID 'planner'와 동일하게 화면 표기).
(4) 모바일에서도 "플래너"로 표시.

7. 지킬 원칙 요약
--------------------------------------------------------------------------------
- 한 화면 고정·페이지 스크롤 금지를 모든 변경의 최우선으로 검증한다.
- 색상군 4개 이내, 상태는 색+글자 함께 표기, 키보드 접근성 유지(Rule_UIUX).
- 내부 식별자(planner 등)·데이터 모델·Vault 저장 형식은 건드리지 않는다(호환 유지).
- 요청과 무관한 코드/스타일은 임의로 리팩토링하지 않는다(외과적 변경).
