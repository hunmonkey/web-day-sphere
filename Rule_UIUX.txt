1-1. 화면 원칙
--------------------------------------------------------------------------------
★ 절대 원칙 — 한 화면 고정, 스크롤 금지 (Rule_Project_Etc.txt와 동일, 최우선)
- 모든 화면은 브라우저 한 화면(뷰포트)에 정확히 들어맞아야 한다.
- 페이지(뷰포트)가 위아래로 내려가거나 좌우로 밀리는 스크롤은 절대 발생시키지 않는다.
- 콘텐츠가 많으면 탭 / 분할 / 요약 / 고정 영역 내부 스크롤로 처리하고, 화면 자체는 움직이지 않게 한다.
- 레이아웃은 100vh/100vw 안에 고정한다. 이 규칙은 다른 어떤 디자인·기능 요구보다 우선한다.

1-3. 색상은 적게, 의미는 분명하게
--------------------------------------------------------------------------------
한 화면에서 눈에 띄는 색상군은 4가지를 넘지 않는다.

1. 바탕색: 앱 배경, 패널 배경, 입력칸 배경
2. 글자/선색: 본문 글자, 설명 글자, 테두리
3. 핵심 액션색: 등록, 저장, 새로고침, 실행 같은 주요 동작
4. 상태색: 정상, 주의, 문제, 삭제 같은 상태 표현

색상이 더 필요해 보이면 색을 추가하기보다 문구, 위치, 굵기, 아이콘, 정렬로 구분한다.

1-4. 접근성 기본
--------------------------------------------------------------------------------
- 모든 버튼, 입력칸, 선택 목록은 Tab 키로 이동할 수 있어야 한다.
- `outline: none`으로 키보드 포커스 표시를 지우지 않는다.
- 아이콘만 있는 버튼을 만들 경우 `aria-label`을 반드시 넣는다.
- 버튼 글자와 배경은 충분히 구분되어야 한다.
- 색상만으로 상태를 구분하지 않는다. `정상`, `주의`, `문제` 같은 글자를 함께 보여준다.

1-5. 한국어 인코딩과 글자 깨짐 방지
--------------------------------------------------------------------------------
한국어 문구가 깨지면 사용자는 기능이 고장났다고 느낀다.

- 한글이 들어간 `.txt` 규정 문서는 UTF-8 BOM으로 저장한다.
  - 이유: Windows PowerShell 5.1 같은 도구는 BOM이 없으면 UTF-8 파일을 다른 문자표로 착각할 수 있다.
  - BOM은 파일 맨 앞에 붙는 작은 이름표 같은 것이다. 이 이름표가 있으면 Windows 도구가 "이 파일은 UTF-8"이라고 더 잘 알아본다.
- `Rule_UIUX.txt`, `Rule_Project_Etc.txt`, `Rule_PW.txt`는 모두 UTF-8 BOM으로 저장한다.
- `Rule_PW.txt`는 내용을 화면에 출력하지 말고, 인코딩 확인도 파일 앞 바이트와 UTF-8 유효성만 확인한다.
- 나중에 `Rule_PW.txt`의 토큰을 프로그램에서 직접 읽어 쓰게 되면, 읽은 문자열 맨 앞의 BOM 문자를 제거한 뒤 사용한다.
  - 이유: BOM은 파일 형식을 알려주는 이름표지만, 토큰 값에 섞이면 보이지 않는 글자가 비밀번호 앞에 붙은 것처럼 처리될 수 있다.
- HTML, CSS, JS, JSON, MD, PY 파일은 UTF-8로 저장한다.
- 관리자 웹 화면의 HTML 파일에는 `<meta charset="UTF-8" />`를 유지한다.
- PowerShell에서 한글 파일을 읽을 때는 아래처럼 인코딩을 지정한다.

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
Get-Content -Raw -Encoding UTF8 -LiteralPath 'Rule_UIUX.txt'
```

- PowerShell에서 한글 `.txt` 파일을 저장할 때는 `-Encoding UTF8`을 명시한다.
  현재 프로젝트의 PowerShell 5.1에서는 이 방식이 UTF-8 BOM으로 저장된다.
- 터미널에 글자가 깨져 보인다고 해서 파일 자체가 깨졌다고 바로 판단하지 않는다.
  먼저 `Get-Content -Encoding UTF8`로 다시 읽어 실제 파일 내용을 확인한다.
- 한국어 문구를 수정한 뒤에는 실제 실행 화면 또는 UTF-8 읽기 명령으로 글자가 깨지지 않는지 확인한다.
- 깨진 문구를 발견하면 디자인 수정과 별개로 우선 고친다.

2. 상태 표시 규정
================================================================================

2-1. 상태 배지 기준
--------------------------------------------------------------------------------
상태는 색상만으로 표현하지 않는다.
항상 문구와 함께 보여준다.

PC 상태:
- 온라인: 초록 계열 + `온라인`
- 오프라인: 빨강 계열 + `오프라인`
- 응답 지연: 노랑 계열 + `응답 지연`
- 미등록: 회색 계열 + `미등록`

작업 상태:
- 대기: 회색 계열 + `대기`
- 전달됨: 파랑 계열 + `전달됨` (클라이언트가 작업을 가져갔지만 아직 시작 전)
- 실행 중: 파랑 계열 + `실행 중`
- 성공: 초록 계열 + `성공`
- 실패: 빨강 계열 + `실패`
- 취소: 회색 계열 + `취소`

2-2. 색상 사용 원칙
--------------------------------------------------------------------------------
- 핵심 액션은 파랑 계열을 사용한다.
- 정상은 초록, 주의는 노랑, 위험은 빨강, 미확인은 회색으로 통일한다.
- 화면 전체를 강한 색으로 덮지 않는다.
- 실패나 위험 상태도 배지, 아이콘, 문구, 위치로 강조하고 배경 전체를 빨갛게 만들지 않는다.
- 새 색을 추가하기보다 기존 상태 의미를 먼저 재사용한다.

5. 버튼과 입력 규정
================================================================================

5-1. 버튼 종류
--------------------------------------------------------------------------------
- 주요 버튼: 새로고침, 저장, 작업 요청
- 보조 버튼: 상세 보기, 닫기, 목록으로
- 위험 버튼: 재부팅, IP 변경, DNS 변경, 설치, 삭제

한 화면에 주요 버튼을 너무 많이 두지 않는다.
위험 버튼은 색상뿐 아니라 위치, 문구, 확인 창으로 구분한다.

5-2. 입력값 검증
--------------------------------------------------------------------------------
- IP, DNS, 게이트웨이는 형식을 바로 검증한다.
- 오류 문구는 입력칸 가까이에 표시한다.
- 변경 전 값과 변경 예정 값을 나란히 보여준다.
- 저장 후 실패가 아니라, 가능하면 입력 중에 잘못된 값을 알려준다.

예:
- `IP 주소 형식이 맞지 않습니다. 예: 192.168.0.50`
- `DNS 주소가 비어 있습니다. 자동 DNS를 사용할지 확인해 주세요.`


6. 문구 규정
================================================================================

6-1. 쉬운 한국어 사용
--------------------------------------------------------------------------------
개발자용 영어 문구를 그대로 보여주지 않는다.

권장:
- `Heartbeat 실패` -> `상태 보고 실패`
- `Unauthorized` -> `권한이 없어 실행하지 못했습니다.`
- `Job queued` -> `작업이 대기열에 등록되었습니다.`
- `Timeout` -> `정해진 시간 안에 응답이 오지 않았습니다.`

6-2. 진행 중 문구
--------------------------------------------------------------------------------
- 작업 요청 중: `작업을 요청하는 중입니다.`
- 클라이언트 대기 중: `클라이언트가 작업을 가져가길 기다리는 중입니다.`
- 실행 중: `클라이언트에서 작업을 실행 중입니다.`
- 성공: `작업이 완료되었습니다.`
- 실패: `작업이 실패했습니다. 이유를 확인해 주세요.`
- 오프라인 PC: `현재 오프라인입니다. 마지막 접속 시간을 확인해 주세요.`
